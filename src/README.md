# lintcha

lint ya charter before it runs. One static site, three languages (en, es, pt-BR), light and dark, nothing pasted leaves the browser and no request leaves the origin.

## layout

- `templates/index.html` (the design shell, 2026-09-06), `templates/method.html`: the two page sources. Markup carries `data-i18n` keys, no user-facing string and no corpus figure lives in markup or in `app.js`; the build fails on a bare figure in template text. `supplied/handoff/` is the shell as delivered.
- `i18n/en.json` (reference, every key), `i18n/es.json` (Spanish), `i18n/pt.json` (Brazilian Portuguese), same keys each. `supplied/en.json.supplied` is the English copy as delivered on 2026-09-05, kept for diffing.
- `job.js`: the job block (input, action, trigger, destination) over the normalized text; feeds the optional third argument of `verdict.js` on the check page only; never scored or counted.
- `verdict.js`: the one mapping from engine values to the check page's pass, miss, note; shared with the library build (`tools/build-library.mjs` at the repository root), pinned by `tests/verdict_test.js`.
- `library.js`, `library.css`: the library catalog filters (state in `location.hash`) and role-page copy button; the pages themselves are rendered into the served tree by `node tools/build-library.mjs`, run after this build.
- `gate.js`: the input gate, decided before any rule runs (profile, too_thin, not_readable); calibrated against the strict corpus with `tools/gate_calibrate.js` (every corpus charter must come back as profile: `node tools/gate_calibrate.js ../work_v4 ../out_v4/gate_calibration.md`).
- `app.js`: page logic, renders results, cards and the comparison block in the shell's markup, reads its strings from the JSON inlined into each page. `ui-controls.js` (theme toggle and language select, see `CONTROLS_CONTRACT.md`) loads first and owns the two storage keys `lintcha:theme` and `lintcha:lang`. `style.css` = `fonts/fontface.css` + the shell's palette and keyframes; `method.css` carries the method page's structural rules.
- `rules.js`: the audit's own engine, generated once by `audit/jsport.py`. Never edited, never regenerated by this build.
- `numbers.json`: byte copy of the frozen numbers file of the current run (`out_v4/numbers_v4.json` since 2026-09-06, the hand-cleaned stage-1 corpus). The build verifies both copies byte for byte.
- `data/sources.json`, `data/r7_rescan.json`: exported by `python -m audit.site_build` for the method page.
- `fonts/`: Archivo (variable, 400 to 600) and IBM Plex Mono 400 and 600, latin woff2, self-hosted (SIL OFL), declared in `fonts/fontface.css`.
- `icon-32.png`, `icon-180.png`, `icon-512.png`, `og.png` (generated outside this build, referenced by every page head and by the generated `manifest.webmanifest`).
- `tools/build.js`: emits `dist/` with `/index.html`, `/method.html` and `/<lang>/` copies of both for every `i18n/<lang>.json`, copies the assets untouched, writes `robots.txt` and `sitemap.xml`. The language list is the set of `i18n/*.json` files; adding a language is one json file plus one `<a>` in the switcher and one hreflang `<link>` in each template.
- `tools/i18n_check.js`: the coverage gate, exits non-zero on a missing key, an empty string, a leftover marker, or a bracket slot / `{var}` that differs between languages.

## ship

Three commands from `site/`, no bundler:

```
node tools/i18n_check.js
node tools/build.js --origin https://your.host
node ../tests/parity.js ../work_v4 ../out_v4/parity_report.md
```

Then drop `dist/` on the host (Cloudflare Pages: static folder, no build command, no server). `dist/_headers` carries the security headers; the build writes the sha256 of the inline theme script into the CSP, so rebuild after any edit to that script. Without `--origin`, og:url, hreflang and the sitemap carry root-relative paths and the build prints a note. Pass the deploy origin so link cards and language alternates resolve. No domain is written into any source file.

The parity test must report every frozen label identical before shipping.

## no typed numbers

No corpus figure is written into markup or translations. Every count, denominator, share, repository row and rule figure is read from `numbers.json` at build time (prerendered pages) and again at runtime (`app.js`), through `{placeholders}` in the strings. Swapping in a new `numbers.json` and rebuilding changes every number on the site with no edit to templates or language files. Meta descriptions carry no figures at all. The source table's branch and commit columns come from `data/sources.json` (the manifest export) looked up by repository name, because `numbers.json` carries no commit SHAs; rows and counts come from `numbers.json`.

## run locally

```
python -m http.server 8000 --directory dist
```

Opening `dist/index.html` directly from disk also works: the strings and the comparison numbers the check page needs are inlined at build time, so no fetch is required. `numbers.json` is still fetched when served over http and is the source of truth.

## language

- Each language is a prerendered page, so a link to `/es/` renders a Spanish card.
- A stored choice (`localStorage` key `lintcha:lang`) wins over the URL; without one, a browser whose language is Spanish or Portuguese is sent from `/` to `/es/` or `/pt/` once. The select stores the choice, fires `lintcha:lang`, and `app.js` navigates to the sibling page. The theme lives in `lintcha:theme`; these are the only two keys the site writes.
- The eight detectors read English only. When the pasted text does not read as English a notice says so; the results are shown anyway. The comparison numbers are counts over English charters in every language.
- Counts keep their digits (`267 of 765` -> `267 de 765`), shares go through `Intl.NumberFormat` for the page locale, the snapshot date stays ISO in every language.

## regenerate the data files

From the repository root, only when the frozen numbers or the manifest change:

```
python -m audit.site_build out_v4/numbers_v4.json work_v4/manifest_stage1.json work_v4/r7_rescan.json
```
